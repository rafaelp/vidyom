# AGENTS.md

Instructions for AI coding agents working in this repository. Humans should start with [README.md](README.md) and [CONTRIBUTING.md](CONTRIBUTING.md).

## Project status

Vidyom is an open-source video editing studio run by AI agents. The first executable version is in this tree and has not been released: nothing is tagged or published. `vidyom`, `vidyomd` and `vidyom-worker` run the whole lifecycle on one host, proven end to end with a fake AI engine, a mock LLM, a mock destination and local storage.

Each source has its own job:

- `docs/status.md`: what the code does today, with its results, mocks, skeletons and gaps. Check it before stating that a feature works.
- `spec/`: what is decided, proposed or pending.
- `docs/decisions.md` and `docs/decisions/`: implementation decisions (`I1, I2, ...`), distinct from the maintainer's `D1–D59` in spec §21.

**Voice (maintainer's decision of 2026-11-09):** `website/` is product copy in the present tense, written as if every roadmap phase were implemented, so it is not evidence that a feature exists. `README.md` keeps the product voice but must agree with `docs/status.md`, and its Status section says what is not ready. `SECURITY.md` stays factual. Everywhere, never invent results, benchmarks, versions, release dates, install commands or legal conclusions, and never claim a **Validate** item has passed (on the website, write it as a check for the operator).

## Repository layout

- `cmd/`: the `vidyom` CLI, the `vidyomd` daemon and the `vidyom-worker` media worker.
- `internal/`: daemon, API, CLI, job engine, persistence, security and the other Go packages.
- `nodes/`: workflow node types. `connectors/`: storage, publishing, AI, transcription, catalog and observability drivers.
- `workflows/`: shipped workflow definitions. `profiles/`: media profiles. `schemas/`: JSON schemas. `plugins/`: the sample plugin.
- `aiworker/`: the Python AI worker. `library/`: the Next.js public library.
- `deploy/`: Dockerfiles and Docker Compose. `config/`: configuration samples.
- `tests/`: integration and end-to-end suites. `scripts/`: the demo and shared tooling.
- `docs/`: status, implementation decisions, build plans and reports.
- `spec/`: the complete product specification the website was derived from. `vidyom-specification-v1.2.md` is current; v1.1 and v1.0 are kept for history. In v1.2, §17 lists what is still open and §21 is the revision log of the maintainer's decisions of 2026-11-08 and 2026-11-09 (marked `(v1.2, Dn)` in the text).
- `website/`: Docusaurus 3 site (TypeScript, React 19).
  - `docs/`: documentation pages, one folder per sidebar category. The sidebar is autogenerated from the folders (`sidebars.ts`).
  - `examples/`: illustrative, non-executable workflow, configuration and media profile JSON.
  - `src/pages/index.tsx`: home page. `src/css/custom.css`: theme and brand colors.
  - `static/img/`: logos, favicon and the workflows overview image.
- `.github/`: CI (`workflows/ci.yml`, `workflows/docs.yml`), Dependabot, issue and pull request templates.
- Root community files: `README.md`, `CONTRIBUTING.md`, `CODE_OF_CONDUCT.md`, `SECURITY.md`, `LICENSE` (Apache-2.0) and `NOTICE`.

## Commands

From the repository root, with Go 1.27, Python 3.12+, Node 22.13+, FFmpeg 5.1+, `sqlite3` and Redis:

```bash
make build          # vidyom, vidyomd and vidyom-worker into bin/
make test           # Go tests
make test-race      # Go tests with the race detector
make test-python    # AI worker tests
make check          # fmt-check, vet, check-static and test
make e2e            # acceptance scenario on the real binaries
make e2e-compose    # the same scenario against Docker Compose
scripts/demo.sh     # the lifecycle for a person to watch, then cleans up
```

From `library/`:

```bash
npm run typecheck && npm run lint && npm test && npm run build && npm run test:e2e
```

From `website/`, with Node.js 20+ (Node 22 recommended):

```bash
npm install
npm run start       # dev server at http://localhost:3000
npm run typecheck   # tsc --noEmit
npm run build       # production build; fails on broken links
```

CI: `workflows/ci.yml` covers Go, Python, the library and `make e2e`; `workflows/docs.yml` runs `npm ci`, `npm run typecheck` and `npm run build` for the website. Run `typecheck` and `build` before finishing any change under `website/`.

## Writing rules

- Everything is written in **English**: documentation, code, comments, UI copy and commit messages.
- In `spec/`, mark requirement status with `[DECIDED]`, `[PROPOSED]`, `[FUTURE]` or `[VALIDATE]`. Never promote a Proposed item to Decided on your own. The website does not use these labels.
- Do not fill pending decisions silently. Open items are listed in spec §17. If a change depends on one, flag it instead of choosing.
- When the website and the spec disagree on anything other than implementation status, point it out rather than resolving it silently.
- Use fictional examples (`ORI-001`, `media.example.internal`). Never include real credentials, tokens, signed URLs or personal data.
- Every docs page needs frontmatter with `title` and `sidebar_position`. Link between docs with relative Markdown paths (`./workflows/create-clip.md`); `onBrokenLinks` is set to `throw`.

## Domain vocabulary

Keep these concepts distinct (see `website/docs/getting-started/concepts.md` and `website/docs/connectors/overview.md`):

- **Node** (workflow action), **connector** (provider driver), **plugin** (distributable package), **hook** (synchronous lifecycle interception) and **event** (asynchronous notification).
- Storage roles `archive`, `master` and `proxy`. Clipping must **never** read from `archive`.
- An **original** is any ingested recording, not only a lecture. Every clip is its own asset with lineage back to its source.

## Architecture at a glance

Decided design choices that are easy to get wrong (details in spec v1.2 §21):

- Multi-tenant from the MVP. One SQLite database per tenant plus a global `system.db`; only the daemon opens database files. No PostgreSQL.
- Redis dispatches jobs; the tenant database is the source of truth for job state.
- Workflow data references use `${...}`; conditions use CEL. Plugins speak JSON-RPC 2.0 over stdio.
- Remote clients use HTTPS with device pairing. Server secrets live in an encrypted per-tenant vault; client machines use the OS keyring.
- Friendly clip IDs use the `CLIP-` prefix. MediaCMS is an optional connector, not the catalog.
- Tenant-scoped API requests carry the `Vidyom-Tenant` header; paths stay tenant-free.
- Go for the CLI, daemon and media worker; Python only for the AI worker. The public library is Next.js.
- The whole project must run on a single host on Linux, macOS or Windows; Docker Compose is the supported path on all three.

## Website styling

- Brand colors are CSS variables in `website/src/css/custom.css`: light-mode primary `#c54b00`, dark-mode primary `#fd8a02` (the logo orange), warm near-black dark backgrounds (`#15110f`).
- Dark-mode overrides must use the `html[data-theme='dark']` selector; plain `[data-theme='dark']` loses to Infima's defaults.
- The navbar uses `img/vidyom-logo.png` and, in dark mode, `img/vidyom-logo-dark.png` (light wordmark).
- In React pages, reference static assets through `useBaseUrl`, because `baseUrl` is configurable via `DOCS_BASE_URL`.
- Mermaid diagrams render through `@docusaurus/theme-mermaid`; their brand colors are the `--mm-*` variables in `custom.css`. Keep the `d3` overrides in `website/package.json` (see `website/README.md`, Dependency notes) unless you verify that hovering diagram nodes logs no errors.

## Git

- The default branch is `main`; the GitHub repository is `rafaelp/vidyom`. The documentation site is deployed on Vercel at https://www.vidyom.org on every push to `main`.
- Always work directly on `main`; do not create branches.
- Write commit messages in English, in the imperative mood.
- Agents can share one working tree: commit with `scripts/commit.sh -m "message" -- path...`, listing explicit paths, and add Go dependencies with `scripts/add-dep.sh`.
- Security issues are reported privately as described in `SECURITY.md`, never in public issues.
